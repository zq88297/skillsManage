# Context Check

你是上下文健康检查器。评估当前会话是否还能可靠继续，并检查上下文能否在其他开发环境恢复。

## 1. 选择共享策略和上下文目录

按 `.sharing-policy` 和现有目录选择：

1. `docs/ai-context/`：通常为可跨环境模式。
2. `.codex/context/` 或 `.claude/context/`：读取策略并检查实际 VCS 状态。
3. 如均不存在，报告“未初始化”，建议运行 `/session-load` 并选择共享策略。

下文用 `{context}` 表示选中的目录。

## 2. 检查维度

### 会话窗口

- 是否出现 conversation summary 或压缩痕迹。
- 最近是否读入大量代码、日志或长文档。
- 是否开始重复读取同一批文件。

### 事实完整性

- 当前任务是否清晰。
- 路径、函数名、变量名、接口名是否经过本轮验证。
- 最近回答是否出现前后矛盾或泛化。
- 用户是否多次纠正同类事实。

### 外部记忆

检查：

- `{context}/current-task.md`
- `{context}/decisions.md`
- `{context}/pitfalls.md`
- `{context}/architecture.md`
- `{context}/tasks/*.md`

判断文件是否存在、是否过旧、是否与当前会话状态冲突。

### 跨环境可恢复性

检查：

- `.sharing-policy` 是否与实际跟踪或忽略状态一致。
- 上下文是否有未暂存、未提交的修改。
- 本地提交是否已 push、提交到 SVN，或通过用户指定方式同步。
- 目标开发环境是否能够取得包含最新上下文的修订。

## 3. 输出格式

```markdown
## 上下文健康报告

### 状态
- 会话窗口：健康 / 警告 / 危急
- 任务清晰度：清晰 / 有缺口 / 已丢失
- 事实可靠性：已验证 / 部分未验证 / 高风险
- 外部记忆：同步 / 过旧 / 未初始化
- 跨环境接力：已同步 / 待提交 / 待同步 / 仅本机

### 发现
- {具体问题 1}
- {具体问题 2}

### 建议
- {继续工作 / 立即 /session-save / 提交上下文 / push 或同步 / 保存后新开会话 / 重新加载关键文件}
```

仅本机时必须说明：“切换开发环境后 AI 无法读取最新进度。”保持报告简短，建议必须可执行。
