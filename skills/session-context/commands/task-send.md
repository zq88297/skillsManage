# Task Send

你是跨项目/跨模块任务派发器。把当前项目中的问题和线索写成结构化任务，发送到目标项目上下文中。

## 参数

`$ARGUMENTS` 是目标路径：

- 绝对路径：`/task-send F:\AICode\project-b`
- 相对路径：`/task-send ..\project-b`
- 子模块名：`/task-send module-a`

未提供路径时，先向用户索要目标路径。

## 1. 解析目标

1. 解析目标路径。
2. 确认目录存在；不存在时询问用户更正或创建。
3. 在目标目录按规则选择上下文：
   - 优先 `{target}/.codex/context/`
   - 兼容已存在的 `{target}/.claude/context/`
   - 都不存在则创建 `{target}/.codex/context/`

## 2. 提取任务信息

从当前会话提取：

- 问题背景：为什么需要目标项目排查。
- 交互关系：API、socket、文件、数据库、消息队列、共享内存等。
- 关键接口：函数、端点、协议字段、配置项。
- 已知线索：日志、错误码、复现步骤、抓包、返回值。
- 已排除项：当前项目已经确认不是问题的范围。
- 建议排查项：目标项目下一步应检查什么。

信息不足时只问缺失的关键问题。

## 3. 创建任务文件

在目标 `{context}/tasks/` 下创建：

`from-{source-project}-{YYYYMMDD-HHmm}-{summary}.md`

内容：

```markdown
# 来自「{来源项目}」的排查任务

> 派发时间：{datetime}
> 来源路径：{source path}

## 问题背景
{问题说明}

## 交互关系
- 调用方式：{方式}
- 发起方：{模块/文件/接口}
- 接收方：{模块/文件/接口}
- 数据流：{输入输出}

## 已知线索
- {线索}

## 已排除
- {已排除范围}

## 排查建议
- [ ] {具体检查项}
- [ ] {具体检查项}

## 相关文件
- {path}:{line} - {说明}
```

## 4. 回写来源项目

在来源项目 `current-task.md` 追加：

```markdown
## 已派发任务
- 时间：{datetime}
- 目标：{target path}
- 文件：{target context}/tasks/{file}
- 状态：等待目标项目排查
```

## 5. 如果当前会话直接排查目标项目

必须回写目标任务文件：

- 有结论：写入结论并移到 `tasks/done/`。
- 部分排查：追加已查范围、排除项、剩余疑点。
- 确认不是目标项目问题：写入排除依据并移到 `tasks/done/`。

避免目标项目下次加载时重复做同一轮排查。

## 6. 输出

```markdown
## 任务已派发

- 来源：{source}
- 目标：{target}
- 任务文件：`{target context}/tasks/{file}`
- 下次处理：目标项目运行 `/session-load`
```
