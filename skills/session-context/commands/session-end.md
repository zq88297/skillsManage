# Session End

你是会话收尾管理器。目标是让下一次会话可以直接接续，而不是重新探索。

## 1. 健康评估

检查：

- 是否出现上下文压缩或 summary。
- 是否有路径、函数名、变量名错误。
- 是否有未保存的计划、验证结果、部署步骤或决策。
- 是否有用户多次纠正的事实。

给出：健康 / 建议新会话 / 必须新会话。

## 2. 生成收尾摘要

摘要必须覆盖：

- 当前任务目标。
- 已完成内容。
- 修改过的关键文件。
- Bug 根因和修复方式（如适用）。
- 运行、测试、构建、部署验证结果。
- 新增依赖、工具链、环境变量或端口。
- 技术决策和放弃的方案。
- 踩坑、根因、预防方式。
- 下次继续的第一步，具体到文件和函数/位置。

如果涉及 Bug 修复，补充复盘：

- 是否属于历史高发类型。
- 经常出错的 Bug 类型。
- 降低复发的流程、提示词、测试或监控优化。

## 3. 写入上下文

按规则选择 `{context}`：

1. 优先 `.codex/context/`
2. 兼容已存在的 `.claude/context/`
3. 都不存在则创建 `.codex/context/`

写入：

- `{context}/current-task.md`：覆盖为最新任务状态，包含“下次继续”和“关键文件清单”。
- `{context}/decisions.md`：追加新决策。
- `{context}/pitfalls.md`：追加新问题、根因和预防。
- `{context}/reference/context-YYYY-MM-DD.md`：保存稳定技术事实。

敏感信息只允许保留在 `current-task.md` 的临时段落；会话结束时应删除或脱敏。

## 4. 输出

```markdown
## 会话已收尾

- 任务进度：已保存到 `{context}/current-task.md`
- 新增决策：N 条
- 新增踩坑：N 条
- 参考资料：N 条
- 健康状态：健康 / 建议新会话 / 必须新会话

下次继续：运行 `/session-load`，然后从 {文件}:{位置} 开始。
```
